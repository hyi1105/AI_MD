# AI 規則（執行前必讀）

## 0. 合作方式（負責人 ↔ AI）

```text
你分享想法／對話
  → AI 整理成清楚條目
  → 寫入 docs/idea.md
  → AI 列出「待確認細節」跟你對過

你確認細節（確認／OK／就這樣／沒意見…）
  → AI **直接開發並發布**（不必再說「改程式」「發布」）
  → 成功後登記 docs/03-checklist.md
  → 該則構想從 idea.md 移到 docs/idea.history.md

之後改版時說「查核 checklist」
  → AI 對照線上／程式，找出缺漏功能
```

| 你做什麼 | AI 做什麼 |
|----------|-----------|
| 分享想法、聊天、語音轉文字 | 改寫繁中、補齊欄位、**只改 MD**，存進 `idea.md`；並列出待確認細節 |
| **確認細節**（確認／OK／就這樣／沒意見等） | **直接開發並發布**上線；成功後登記 checklist，構想移 `idea.history` |
| 說「查核／對照 checklist」 | 讀 `03-checklist`＋現況，回報缺漏 |
| （可選）仍說「改程式」／「發布」 | 同等觸發開發／上線（舊詞仍有效） |

**硬規則**：細節**未**跟負責人確認前，只改 MD、不動 code、不上線。確認後不必再等第二次口令。

## 1. 文件定位

| 檔案 | 定位 |
|------|------|
| [`docs/idea.md`](../docs/idea.md) | **進行中**構想（對話整理後存放處） |
| [`docs/idea.history.md`](../docs/idea.history.md) | **已結案**構想归档（舊名 `02-idea-done`）；與 idea 分開＝少載入、省成本 |
| [`docs/03-checklist.md`](../docs/03-checklist.md) | **現有功能查核表**；改版後對照現況，發現缺漏 |

另：[`docs/00-theme.md`](../docs/00-theme.md) 主題 · [`docs/ai-doc.md`](../docs/ai-doc.md) AI Doc 規格 · `.mdc` 見 00-theme。

禁止再新建 STATUS／HOW／gap。  
禁止把「還沒做過的空想」塞進 checklist。

## 2. 語言（一律繁體中文）

- 回覆、文件、構想整理：**繁體中文**。  
- 語音轉文字若英／簡／錯字：入檔時改寫正確繁中。  
- 僅路徑／API／ID 可英文。

## 3. 命名

| 名稱 | 意思 |
|------|------|
| Theme | `00-theme.md` |
| Idea | `idea.md`（進行中）／`idea.history.md`（已結案） |
| 文稿／AI Doc | **AI Doc**：像 Cursor 改檔並顯示修改處（舊稱 SmartDoc／文稿） |

## 4. 目錄

只維護 `web/catalog.json`。  
目錄變更：負責人說「改目錄」，或**已確認細節的開發**本身需要改目錄時才改。

---

## 5. 流轉

```text
對話／想法 → AI 整理 → idea.md → 列出待確認細節
  → 負責人確認細節
  → AI 直接開發並發布
  → 登記功能到 03-checklist.md（供日後查核）
  → 該則構想移到 idea.history.md（讓 idea.md 保持精簡）
```

---

## 6. 寫入 Idea 的品質（必守）

每則 `idea.md` 至少含：Why／What／How／Pros／Cons／替代方案／完成後列入 checklist 的查核句／待拍板（待確認細節）。

---

## 7. 說明法（給解法／結構／程式時必守）

> 負責人**記路線很強**：只要**真實結構＋簡短介紹**；旁註口語「都在這裡面／放這」。  
> **一次條列 ≤ 5**。不要「走進房間」等比喻（會突然看不懂）。

### 負責人記憶法（必守）

1. **真實路徑樹**；錨點＝實際檔案／資料夾。  
2. **父層同行介紹**＋子層同行旁註；語氣＝「都在這裡面／放這…」。  
3. **一次最多 5 條**；下一批 ≤5 **直接接在下面**（同一則或下一則都可，不必等「繼續」）。  
4. 程式碼最後、可省略。  
5. 禁止：房間／故事比喻、虛流程、職稱標籤腔、一次 >5、卡關等「繼續」才給下一段。

### 一則的樣子（範本＝負責人定稿）

```text
web/ 客人在網上看的東西都在這裡面
├── index.html     — 一進來先看到的那頁放這
├── query.html     — 要查工具時開的頁面放這
├── catalog.json   — 工具名單資料都寫在這一份
├── approval/      — 簽核相關的示範畫面都放這
└── system-map/    — 系統地圖相關畫面都放這

├── tool.html      — 看單一工具詳情的頁面放這
├── tool.js        — 上面那頁會用到的程式放這
├── script.js      — 查詢頁會用到的程式放這
├── shared.js      — 好多頁共用的程式放這
└── style.css      — 網站看起來長怎樣的樣式放這
```

> 同一父層下一批：空一行後直接再列 ≤5，**不要**再寫 `web/（接續）`。  
> 換到別的父層才新開一行 `path/ 介紹…`。

### 微調紀錄

| 來源 | 寫進規則 |
|------|----------|
| 真實 path＋同行介紹；一次 ≤5 | 正式記憶法 |
| 旁註＝都放這口語；禁職稱標籤 | 描述方式 |
| 「不要走進房間；只要結構跟介紹」 | 範本以上方定稿為準 |
| 「ok 了接著下一段；不要等我說繼續」 | 下一批直接接續出現 |
| 接續批次不要重複父層標題 | 空一行再列即可 |
| 「太讚了 這是我要的」 | 說明法定稿確認 |

### 不做

- 不做站上產品頁（另開 idea）。  
- 不要房間比喻、不要一次超過 5 條。
