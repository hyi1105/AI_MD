# AI 規則（執行前必讀）

## 0. 合作方式（負責人 ↔ AI）

```text
你分享想法／對話
  → AI 整理成清楚條目
  → 寫入 docs/idea.md
  → AI 列出「待確認細節」跟你對過

你確認細節（確認／OK／就這樣／沒意見…）
  → AI **直接開發並發布**（不必再說「改程式」「發布」）
  → 成功後登記 docs/03-checklist.md
  → 該則構想從 idea.md 移到 docs/idea.history.md

之後改版時說「查核 checklist」
  → AI 對照線上／程式，找出缺漏功能
```

| 你做什麼 | AI 做什麼 |
|----------|-----------|
| 分享想法、聊天、語音轉文字 | 改寫繁中、補齊欄位、**只改 MD**，存進 `idea.md`；並列出待確認細節 |
| **確認細節**（確認／OK／就這樣／沒意見等） | **直接開發並發布**上線；成功後登記 checklist，構想移 `idea.history` |
| 說「查核／對照 checklist」 | 讀 `03-checklist`＋現況，回報缺漏 |
| （可選）仍說「改程式」／「發布」 | 同等觸發開發／上線（舊詞仍有效） |

**硬規則**：細節**未**跟負責人確認前，只改 MD、不動 code、不上線。確認後不必再等第二次口令。

## 6. 寫入 Idea 的品質（必守）

每則 `idea.md` 至少含：Why／What／How／Pros／Cons／替代方案／完成後列入 checklist 的查核句／待拍板（待確認細節）。

## 7. 說明法（給解法／結構／程式時必守）

> 負責人**記路線很強**：要先有**錨點**，旁邊一句「這是什麼」；記憶時**結構要跟著出現**。  
> 不是純故事長講（會抓不到重點）；也不是一次倒完再對照。

### 負責人記憶法（必守）

1. **先給路線**：少數錨點串成一條路（例如 `A → B → C`），讓結構一眼在旁邊。  
2. **每個錨點一句話**：這是什麼／為什麼在這裡（極短）。  
3. **一則只走一小段路**：不要整庫一張牆；下一段等他說「繼續」。  
4. **檢查點最多 1 個**（或只問要不要下一段）；禁止章末三題總複習。  
5. **程式碼最後、可省略**；絕不要開頭大段程式。

### 一則的樣子（範本）

```text
路線：錨1 → 錨2 → 錨3

錨1 — 一句：這是什麼
錨2 — 一句：這是什麼
錨3 — 一句：這是什麼

（要不要走下一段？）
```

### 微調紀錄

| 來源 | 寫進規則 |
|------|----------|
| 最怕開頭大段程式 | 程式永遠最後 |
| 一次講完＋多題對照 | 禁止 |
| 「純故事抓不到重點」 | 改為路線＋錨點＋旁註 |
| 「記路線很強；先錨點；旁邊簡單講；結構要出現」 | 正式記憶法 |
| 舊「同則檔案牆／三題／長故事一章」 | 作廢 |

### 不做

- 不做站上產品頁（另開 idea）。  
- 不要長故事無結構、不要目錄牆、不要一次講完再對照。
