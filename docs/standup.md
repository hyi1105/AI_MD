> 更新方式：每次會議或討論後，在**最上方**新增一個日期區塊。  
> **任務執行**請開 [GitHub Issues](https://github.com/hyi1105/AI_MD/issues)；這裡只記「畫面問題、決策、誰 approve 了什麼」。

## 團隊工作方式（共識）

| 角色 | 做什麼 | 不做什麼 |
|------|--------|----------|
| **團隊（5 位同事）** | 對**畫面**提問題、驗收、截圖、描述期望 | 不直接改 code（除非負責人指定） |
| **AI（Cursor）** | 預設只改 MD（繁中）；下令後才改程式／發布；回寫 STATUS | 不自行決定產品方向；未下令不改 code |
| **負責人（你）** | Approve AI 做不到的事：對外上線、帳密、付費、法務、重大取捨 | 不包辦每行 code review |

### 問題怎麼提（給同事）

請用**畫面語言**，AI 比較改得準：

- ✅「搜尋結果卡片在手機上按鈕會擠在一起」
- ✅「詳情頁 Markdown 標題太大，想小一級」
- ❌「改 script.js 第 120 行」（留給 AI）

### 實作怎麼走

1. 同事在 Issue 或本檔「畫面問題」區塊描述問題  
2. 指定人（或輪值）在 Cursor 用 `@docs/01-requirements-master.md` + Issue 請 AI 改  
3. AI 開 PR → 同事看**線上或本機畫面**是否 OK  
4. 需你 approve 的項目（見下方清單）→ 你在 PR 或本檔勾選後才 merge  

### 需負責人 Approve 的事項

- [ ] 公開對外公告、自訂網域、SEO 重大改動  
- [ ] 新增/刪除整個功能模組（超出 F-01～F-10 範圍）  
- [ ] 第三方 API、登入、付費、追蹤像素  
- [ ] 授權、隱私、使用者資料如何存放  
- [ ] AI 與同事意見衝突時的最終決策
