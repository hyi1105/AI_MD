### 寫入規則（給 AI）

負責人每說一則構想（含語音轉文字），AI 必須：

1. 改寫成**繁體中文**  
2. 用下方完整模板補齊（缺的標「待補／待拍板」）  
3. **追加**到本檔最上方  
4. 未真正具備的功能不要塞進 checklist；checklist 只登記「現在應該查核得到」的能力  

### 完整模板（每則必用）

```markdown
## YYYY-MM-DD — 短標題
- 狀態：open｜building｜waiting-owner
- 來源：對話／語音轉文字（可註原文關鍵句）
- 為什麼（Why）：要解決什麼問題？不做會怎樣？
- 做什麼（What）：使用者會看到／能完成的具體結果（1～3 句）
- 怎麼做（How）：實作方向、改哪些檔／流程、依賴什麼
- 優點（Pros）：做成後的好處
- 缺點／風險（Cons）：成本、複雜度、安全、維護、對現有功能影響
- 不做的替代方案：若不做，有沒有較小做法？
- 完成後列入 checklist：查核句（給 checklist 用，描述「產品應具備的功能」）
- 待拍板：需要負責人決定的問題（無則寫「無」）
```

## 2026-08-13 — 系統分層認識＋多視角統一場景

- 狀態：open  
- 來源：對話（原文關鍵：「layer by layer」「兩個結構展開」「SQL／Shared Enclosure／流程圖／Power Automate 都看到類似場景」）  
- 為什麼（Why）：認識全新系統時，容易被細節淹沒、各工具語法／圖面各自為政，無法在腦中對齊「同一層在講什麼」。沒有統一骨架，換到 SQL、Shared Enclosure、流程圖、Power Automate 就像換了另一套世界，學習成本與溝通成本都高。  
- 做什麼（What）：  
  1. **學習法**：用「大結構 → 中結構 → 小細節」由外而內展開；第一層先鎖定少數主幹（常是 2～3 個），再逐層展開功能。  
  2. **產品／知識呈現**：同一套「系統地圖」可切換視角——進 SQL 就長成 SQL 場景、進 Shared Enclosure 就長成 Enclosure 場景、進流程圖／Power Automate 同理——但**層級、節點、關係仍對齊**，讓人感覺在同一張地圖上換鏡頭，而不是換地圖。  
- 怎麼做（How）：  
  - **認識骨架（建議固定欄位）**：每一層節點都用同一張卡：名稱／職責／輸入／輸出／依賴／邊界／下一步可展開的子節點。  
  - **第一層策略**：先找「主幹結構」而非功能清單（例：請求進／結果出、資料存／流程控、人或系統的責任分界）。通常 2～3 個主幹就夠；多了就不是第一層。  
  - **展開規則**：大 → 中 → 小；同一深度先橫向對齊再往下鑽，避免一條線鑽到底其餘空白。  
  - **統一場景（多視角）**：底層一份「系統層級模型」（節點＋邊＋層級）；各視角是投影——流程圖＝流程邊、SQL＝資料／查詢邊、Power Automate＝自動化動作邊、Shared Enclosure＝空間／權限／共置邊。與現有 AI Doc「同一份檔、多模式預覽」同構，可延伸為「系統知識書」的多視角。  
  - **互補學習法（建議一併寫進知識書方法論）**：  
    1. 跟一筆交易／一次請求走完全程（縱切）；  
    2. 先畫邊界與接口，再填內部（接口優先）；  
    3. 對照「同構視角」驗證理解（換視角後節點還對得上才算懂）。  
  - 實作若做產品：資料模型（節點／邊／層／視角投影）→ 知識書架或 AI Doc 多模式 → 示範一本「某系統」知識書。依賴：主題知識書路線；可先 MD／靜態示意，不需先上真 LLM。  
- 優點（Pros）：學習有地圖可循；跨工具溝通有共同座標；與主題「知識書／累積專業」高度契合；可複用 AI Doc 多模式預覽概念。  
- 缺點／風險（Cons）：統一模型若設計過重會變成抽象稅；不同領域硬套同一層級可能失真；Shared Enclosure／PA／SQL 等領域詞彙需負責人定「視角清單」與範例系統，否則易空轉。  
- 不做的替代方案：先只寫一篇「怎麼認識新系統」方法論文（無產品 UI）；或只做單一系統的靜態分層 MD＋幾張對照圖。  
- 完成後列入 checklist：能打開同一系統地圖並在至少兩種視角（例如流程圖與 SQL）之間切換，且層級節點仍對齊可辨識。  
- 待拍板：  
  1. 這則偏「方法論寫進知識書」還是「要做可切換視角的產品 UI」？  
  2. 第一本示範系統選哪個（含 Shared Enclosure／SQL／流程／PA 的真實範例）？  
  3. 視角清單定稿：SQL／Shared Enclosure／流程圖／Power Automate 是否就這四個起跳？
