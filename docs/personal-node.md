# 個人節點（Personal Node）— 系統核心架構

> 狀態：已定為 **系統核心**（負責人夙願）  
> 關聯：[`idea.md`](./idea.md) · 可感受第一刀：[`../web/node/`](../web/node/) · 主題：[`00-theme.md`](./00-theme.md)  
> 更新：2026-08-16

---

## 1. 一句話

**平台只提供連線；認證與資料實體住在使用者自己的裝置上。**  
簽核、對話等能力以**去中心**方式提供，目標是個人／一人公司也能辦到現在多半只有企業才辦得到的事。

---

## 2. 為什麼是核心

| 舊世界 | 個人節點世界 |
|--------|----------------|
| 資料與帳號在公司雲／SaaS | 資料在你的手機或常開的過期手機 |
| 平台＝主庫＋算力＋帳號 | 平台＝連線／發現／靜態工具頁 |
| 個人只能當租戶 | 個人＝節點擁有者（個人化公司） |

類比：以前的 **Foxy**——你的機器常開、資料在你那邊；網路比較像把人連起來，而不是把檔案收進平台倉庫。

---

## 3. 分層（架構）

```text
SEED 個人節點架構
├── 連線層（平台）
│   — 靜態站、工具頁、（未來）發現／轉送訊號
│   — 不預設持有簽核／對話主資料
├── 節點層（使用者裝置）
│   — 日常手機：隨身操作
│   — 常開存取機：過期手機一直開著，當「個人機房」存取點
└── 服務能力（去中心）
    — 簽核、對話、（未來）知識書／其他企業級能力
    — 狀態與憑證以節點為準
```

### 3.1 連線層（平台）

- 現況：GitHub Pages 靜態站＝幾乎零營運成本的連線與 UI 殼。  
- 職責：讓人打開工具、交換同步包／（未來）交換連線訊號。  
- **禁止預設**：把簽核正文、對話內容、認證私鑰當成平台資料庫欄位。

### 3.2 節點層（裝置）

| 角色 | 意思 |
|------|------|
| 日常手機 | 人正在用的操作端 |
| 常開存取機 | 沒在主力使用、但一直開機連網的手機／專屬機，專門當資料存取處 |
| 專屬裝置 | 同一概念的硬體型（未來） |

第一刀實作：瀏覽器 **本機儲存（IndexedDB）＝這台裝置上的節點庫**；用 **匯出／匯入同步包** 模擬「把主庫放到常開機」。

### 3.3 服務能力（去中心）

優先對齊：

1. **簽核**（表單狀態、核准／退回）  
2. **對話**（簽核脈絡中的訊息流）  

兩者的主狀態都應可只存在節點上，不依賴中心伺服器 session。

## 4. 資料流（第一刀可感受）

```text
裝置 A（日常）                連線層（本站）              裝置 B（常開過期手機）
├── 節點庫：簽核＋對話  —匯出同步包→  只傳檔／開頁面  —匯入→  節點庫接手常駐
└── 操作 UI（/node/）         不存主資料                 之後可從 B 繼續開
```

驗收感覺：關掉分頁再開，資料還在；清站台 cookie／本機庫才會丟；匯出檔可以拿到另一瀏覽器／另一裝置還原。
