# AI 規則（執行前必讀）

## 0. 合作方式（負責人 ↔ AI）

```text
你分享想法／對話
  → AI 整理成清楚條目
  → 寫入 docs/idea.md
  → AI 列出「待確認細節」跟你對過

你確認細節（確認／OK／就這樣／沒意見…）
  → AI **直接開發並發布**（不必再說「改程式」「發布」）
  → 成功後登記 docs/checklist.md
  → 該則構想從 idea.md 移到 docs/idea.history.md

之後改版時說「查核 checklist」
  → AI 對照線上／程式，找出缺漏功能
```

| 你做什麼 | AI 做什麼 |
|----------|-----------|
| 分享想法、聊天、語音轉文字 | 改寫繁中、補齊欄位、**只改 MD**，存進 `idea.md`；並列出待確認細節 |
| **確認細節**（確認／OK／就這樣／沒意見等） | **直接開發並發布**上線；成功後登記 checklist，構想移 `idea.history` |
| 說「查核／對照 checklist」 | 讀 `checklist`＋現況，回報缺漏 |
| （可選）仍說「改程式」／「發布」 | 同等觸發開發／上線（舊詞仍有效） |

**硬規則**：細節**未**跟負責人確認前，只改 MD、不動 code、不上線。確認後不必再等第二次口令。

## 1. 文件定位

| 檔案 | 定位 |
|------|------|
| [`docs/idea.md`](../docs/idea.md) | **進行中**構想（對話整理後存放處） |
| [`docs/idea.history.md`](../docs/idea.history.md) | **已結案**構想归档（舊名 `02-idea-done`）；與 idea 分開＝少載入、省成本 |

另：[`docs/theme.md`](../docs/theme.md) 主題 · [`docs/ai-doc.md`](../docs/ai-doc.md) AI Doc 規格 · `.mdc` 見 theme。

禁止再新建 STATUS／HOW／gap。  
禁止把「還沒做過的空想」塞進 checklist。

- 回覆、文件、構想整理：**繁體中文**。  
- 語音轉文字若英／簡／錯字：入檔時改寫正確繁中。  
- 僅路徑／API／ID 可英文。

只維護 `web/catalog.json`。

## 5. 流轉

```text
對話／想法 → AI 整理 → idea.md → 列出待確認細節
  → 負責人確認細節
  → AI 直接開發並發布
  → 登記功能到 checklist.md（供日後查核）
  → 該則構想移到 idea.history.md（讓 idea.md 保持精簡）
```

## 6. 寫入 Idea 的品質（必守）

每則 `idea.md` 至少含：Why／What／How／Pros／Cons／替代方案／完成後列入 checklist 的查核句／待拍板（待確認細節）。

## 7. 說明法（讀文件／讀程式／給解法時必守）

> **定稿名稱：說明法**（口令也可說「用說明法」「結構＋介紹」）。  
> 適用：**讀 repo 結構、讀文件、讀原始碼、講解法、欄位血緣、請跑指令前介紹**。  
> 負責人確認：「非常好／可以／還願意閱讀完」——含**欄位血緣**呈現。

### 新對話怎麼自動知道？

| 範圍 | 怎麼生效 |
|------|----------|
| **這個 repo** | `.cursor/rules/說明法.mdc`＋其他 `.mdc`＋本檔 §7 → **開新對話就應自動遵守** |
| **你隨口提醒** | 說「用說明法」或「結構＋介紹」 |
| **其他 repo** | ① 複製 `.cursor/rules/說明法.mdc` 到該 repo；或 ② 把口令卡貼進 Cursor **User Rules**（所有專案） |

**口令卡（可複製）：**

```text
用說明法：真實結構樹＋同行簡短介紹；一次≤5；空一行接續；
左邊盡量原始碼／原文；一層一層（先外層再進 if／for）；
不要房間比喻、不要職稱標籤腔、不必等我說繼續。
請我跑 .ps1／指令前，先用說明法講清楚，等我理解同意再跑。
詳見 prompts/AGENT-MASTER.md §7（若在本 repo）。
```
### 規則（必守）

1. **真實結構樹**（檔案 path、文件標題、程式函式／if／for、**欄位名／血緣節點**）。  
2. **父層同行介紹**＋子層同行旁註；語氣「都在這裡面／放這…」。  
3. **一次最多 5 條**；下一批空一行直接接（不必等「繼續」）。  
4. **讀原始碼／血緣**：左邊貼近原文（少用 `...`）；**一層一層**——先外層或先選一個起點欄位，再往下游／上游。  
5. 程式碼大段本體可放最後或省略。  
6. **請跑 `.ps1`／指令前**：先用說明法講「會動到什麼／不會動什麼／跑完會長怎樣」；**等負責人理解並同意後再跑**；禁止沒介紹就叫 Run。  
7. **欄位血緣**：先「欄位從哪來」（規格／畫面／程式／存哪），再挑**一條欄位**從頭走到尾；有條件血緣（required_when）與名字不一致處要標出。  
8. 禁止：房間／故事比喻、虛流程、職稱標籤腔、一次 >5。

### 範本（負責人定稿）

**檔案／資料夾：**

```text
web/ 客人在網上看的東西都在這裡面
├── index.html     — 一進來先看到的那頁放這
├── query.html     — 要查工具時開的頁面放這
├── catalog.json   — 工具名單資料都寫在這一份
├── approval/      — 簽核相關的示範畫面都放這
└── system-map/    — 系統地圖相關畫面都放這

├── tool.html      — 看單一工具詳情的頁面放這
├── tool.js        — 上面那頁會用到的程式放這
├── script.js      — 查詢頁會用到的程式放這
├── shared.js      — 好多頁共用的程式放這
└── style.css      — 網站看起來長怎樣的樣子放這
```

**程式（讀懂原始碼／一層一層）：**

```text
function doSubmit() { 真的送出申請
├── const gaps = requiredGaps();
│     — 先問還缺什麼
├── if (gaps.length) { ... return; }
│     — 有缺就不往下送
├── markMissing([]);
│     — 沒缺就清紅字
├── status = "submitted";
│     — 狀態改成已送出
└── appendSystem({...}); showToast(...); refreshPrimaryAction();
      — 留訊息、提示、更新大按鈕
```

下一層再展開 `if (gaps.length)` 裡面的原文。

**請跑腳本前（`.ps1`／指令）：**

```text
web/start-local.ps1 本機把網站開起來用（你同意後再跑）
├── Set-Location .../web
│     — 先切到網站資料夾
├── 啟動本機伺服器（靜態檔）
│     — 用瀏覽器看現在的頁面
└── 不會改 catalog.json、不會部署上線
      — 只是本機預覽
```

**欄位血緣（負責人確認可讀完）：**

```text
leave_type 假別（跟一條欄位從頭走到尾）
├── schema: "name": "leave_type"
│     — 規格裡叫這個名字
├── index.html: name="leave_type"
│     — 畫面上的下拉選單就是它
├── requiredGaps() 會掃 data-required
│     — 空的就不能送出
├── doSubmit() → status = "submitted"
│     — 送出後這張單進已送出
└── conversation.default_bound_fields 含 "leave_type"
      — 規格說對話預設可綁這個欄位
```

### 微調紀錄

| 來源 | 寫進規則 |
|------|----------|
| 真實 path＋同行介紹；一次 ≤5 | 正式記憶法 |
| 旁註＝都放這口語；禁職稱標籤 | 描述方式 |
| 不要房間比喻；只要結構＋介紹 | 定稿 |
| 下一批直接接續；空一行即可 | 節奏 |
| 函式／if／for；左邊貼近原文；一層一層 | 讀碼 |
| 跑 .ps1 前先說明，同意後再跑 | 指令前 |
| 「血緣可以；還願意閱讀完」 | 欄位血緣定稿 |

### 不做

- 不做站上產品頁（另開 idea）。  
- 不要房間比喻、不要一次超過 5 條。
