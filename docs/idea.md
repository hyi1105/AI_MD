# Idea（進行中的構想）

> 用途：你分享想法 → AI 整理對話 → **寫入本檔**。  
> 與 [`idea.history.md`](./idea.history.md) 分開：查構想時先讀本檔即可，**少載入舊資料、省成本**。  
> [`03-checklist.md`](./03-checklist.md) 是「現有功能查核表」，不是構想匣。  
> 做成並發布後：把該能力**登記進 checklist**；本則構想再移到 `idea.history`。  
> 合作規則總表：[`../prompts/AGENT-MASTER.md`](../prompts/AGENT-MASTER.md)  
> 更新：2026-08-04

### 寫入規則（給 AI）

負責人每說一則構想（含語音轉文字），AI 必須：

1. 改寫成**繁體中文**  
2. 用下方完整模板補齊（缺的標「待補／待拍板」）  
3. **追加**到本檔最上方  
4. 未真正具備的功能不要塞進 checklist；checklist 只登記「現在應該查核得到」的能力  

### 完整模板（每則必用）

```markdown
## YYYY-MM-DD — 短標題
- 狀態：open｜building｜waiting-owner
- 來源：對話／語音轉文字（可註原文關鍵句）
- 為什麼（Why）：要解決什麼問題？不做會怎樣？
- 做什麼（What）：使用者會看到／能完成的具體結果（1～3 句）
- 怎麼做（How）：實作方向、改哪些檔／流程、依賴什麼
- 優點（Pros）：做成後的好處
- 缺點／風險（Cons）：成本、複雜度、安全、維護、對現有功能影響
- 不做的替代方案：若不做，有沒有較小做法？
- 完成後列入 checklist：查核句（給 checklist 用，描述「產品應具備的功能」）
- 待拍板：需要負責人決定的問題（無則寫「無」）
```

## 2026-08-04 — 假圖：聊天氣泡內綠色漸層標籤框
- 狀態：waiting-owner
- 來源：對話（原文關鍵句：「I want such a green box gradient For the fake picture, do not create other functions quickly legitimate token」＋參考截圖：深色聊天、白底欄位標籤）
- 為什麼（Why）：要快速做出／對齊「假圖」視覺——氣泡內像表單欄位的標籤框，但改成**綠色漸層**；不做會缺設計參考或假圖素材不一致
- 做什麼（What）：一張（或一組）假圖／Mock，風格對齊參考聊天 UI（發送者、時間戳、氣泡、欄位標籤＋值）；標籤框為**綠色漸層圓角方框**（非原圖白底黑字、非紫氣泡主題）。**不新增其他產品功能**
- 怎麼做（How）：
  - 僅產出假圖／靜態設計參考（已放 `docs/assets/fake-chat-green-gradient-boxes.png`）
  - 視覺重點：標籤框 `linear-gradient`（約中綠→亮綠）、圓角、粗體標籤字、右側一般訊息文字
  - **禁止**：另開工具頁、改 catalog、改 AI Doc／查詢邏輯、假造或濫用 token／金鑰
  - 未說「改程式」前：**不改產品 code**
- 優點（Pros）：視覺對齊快；範圍極小、不污染產品功能
- 缺點／風險（Cons）：假圖非可互動元件；漸層色值／圓角需負責人拍板後才可進正式 UI
- 不做的替代方案：直接用原參考截圖白底標籤；或只寫 CSS 變數備註、不出圖
- 完成後列入 checklist：無（純假圖／設計參考，非產品功能；若日後「改程式」做成正式元件再登記）
- 待拍板：
  1. 漸層色碼與圓角是否定版？
  2. 假圖用途僅內部參考，還是要掛站／進某個頁？
  3. 是否要說「改程式」做成可重用的標籤元件？

### 主題／知識書

#### 知識書架（瀏覽／發布）
- 狀態：open  
- 為什麼（Why）：主題是知識書，沒有書架就只剩工具  
- 做什麼（What）：使用者可瀏覽、發布自己的知識書  
- 怎麼做（How）：新頁面／資料模型；與 AI Doc 輸出銜接（待設計）  
- 優點（Pros）：產品本體出現
