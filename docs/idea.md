# Idea（進行中的構想）

> 用途：你分享想法 → AI 整理對話 → **寫入本檔**。  
> 與 [`idea.history.md`](./idea.history.md) 分開：查構想時先讀本檔即可，**少載入舊資料、省成本**。  
> [`03-checklist.md`](./03-checklist.md) 是「現有功能查核表」，不是構想匣。  
> 做成並發布後：把該能力**登記進 checklist**；本則構想再移到 `idea.history`。  
> 流轉：**想法 → idea → 確認細節 → 直接開發並發布**（見 AGENT-MASTER）。  
> 合作規則總表：[`../prompts/AGENT-MASTER.md`](../prompts/AGENT-MASTER.md)  
> 更新：2026-08-16（追加：個人化公司／地端主權）

### 寫入規則（給 AI）

負責人每說一則構想（含語音轉文字），AI 必須：

1. 改寫成**繁體中文**  
2. 用下方完整模板補齊（缺的標「待補／待拍板」）  
3. **追加**到本檔最上方  
4. 未真正具備的功能不要塞進 checklist；checklist 只登記「現在應該查核得到」的能力  

### 完整模板（每則必用）

```markdown
## YYYY-MM-DD — 短標題
- 狀態：open｜building｜waiting-owner
- 來源：對話／語音轉文字（可註原文關鍵句）
- 為什麼（Why）：要解決什麼問題？不做會怎樣？
- 做什麼（What）：使用者會看到／能完成的具體結果（1～3 句）
- 怎麼做（How）：實作方向、改哪些檔／流程、依賴什麼
- 優點（Pros）：做成後的好處
- 缺點／風險（Cons）：成本、複雜度、安全、維護、對現有功能影響
- 不做的替代方案：若不做，有沒有較小做法？
- 完成後列入 checklist：查核句（給 checklist 用，描述「產品應具備的功能」）
- 待拍板：需要負責人決定的問題（無則寫「無」）
```

## 未上線構想（展開）

### 個人化公司／地端主權

#### 個人化公司：單獨服務＋資料在使用者裝置
- 狀態：open  
- 來源：對話（「單獨提供服務」「認證／資料實體在手機或專屬裝置／過期手機內建 APP 同步」「未來個人化公司應無成本處理」「從最熟悉的工具開始，例如還沒在用手機的人」「功能等同現在一家企業才能辦到的事」）  
- 為什麼（Why）：企業級能力（簽核、流程、知識累積、對外服務）被鎖在貴、集中、要帳號的雲端／公司系統裡；個人與小單位要嘛用不起、要嘛把資料交給別人。不做就繼續「只有公司能辦、個人只能當租戶」。  
- 做什麼（What）：產品以**單獨服務**出現（可各自用、不必綁一整包企業平台）；**認證與資料實體**預設住在使用者手機，或一台專門存資料的裝置（例如過期手機裝同步 APP、或專屬儲存盒）；營運側朝**無成本處理**個人化公司流程；入門從對方**最熟悉的工具**開始（含「還沒在用手機」的情境，不強迫先換新裝置生態）。目標能力對齊「現在一家企業才辦得到」的事，但尺度是個人／一人公司。  
- 怎麼做（How）：方向待設計——可能疊在現有 SEED 工具（說明法、AI Doc、簽核 Demo、Mermaid、本機 BYOK）的「本機優先」精神上；裝置端同步／離線主庫／可選專屬機；服務可拆成獨立頁或獨立 App。細節未拍板前**只留構想，不改程式**。  
- 優點（Pros）：資料主權清楚；降低月費與平台鎖定；過期手機／專屬機可當「個人機房」；對齊主題「長期關注 × 知識累積」但把主權放使用者端；與現有 BYOK／靜態站無後端金鑰的取捨一致。  
- 缺點／風險（Cons）：裝置遺失／損壞＝資料風險；同步與備份要設計；「無成本處理」與真實算力／頻寬仍有張力；跨裝置與非手機族群的 UX 難；法規（個資、電子簽）若要做到企業同等效力會變重；範圍很大，易做成空想。  
- 不做的替代方案：繼續雲端帳號＋本站示範工具；或只做「匯出／自備金鑰」而不做裝置端實體庫。  
- 完成後列入 checklist：個人可在自有裝置上單獨使用等同企業級的一項完整流程（待拍板是哪一項），且認證／主資料不預設住在本站伺服器  
- 待拍板：  
  1. 第一個「企業級」能力要對齊哪一件？（簽核／知識書／對外服務／其他）  
  2. 第一版儲存形態：只手機／過期手機同步／專屬裝置／先瀏覽器本機？  
  3. 「無成本」是指使用者零月費、還是平台近零營運成本、或兩者都要？  
  4. 「沒在用手機」的第一入口是什麼？（紙本／電腦瀏覽器／電話／其他）  
  5. 這則是產品遠景錨點，還是本季要拆成可上線的一小步？  

### 合作／說明方式

#### 說明法擴充：非線性流程／血緣／其他類型
- 狀態：open（**血緣已定稿**；**非線性流程＝好像還行／可先用**；其餘待試）  
- 來源：對話（可試類型→血緣定稿；STP_I_0022 圖試非線性→「好像還行」）  
- 為什麼（Why）：非線性圖若一次倒完難讀；需同一節奏拆「系統欄→時間圈→檔案血緣」。  
- 做什麼（What）：非線性可先用：先三欄系統、再紅圈 1／2／3、再跟 RCV→INV→INVACK；血緣已定稿。  
- 怎麼做（How）：對話呈現；素材可用簽核圖／外部流程圖；確認「這是我要的」後再寫死 §7。  
- 優點（Pros）：願意讀完的節奏可覆蓋跨系統傳檔圖。  
- 缺點／風險（Cons）：「好像還行」≠完全定稿；分叉多時可能還要再拆。  
- 不做的替代方案：只看原圖、不用說明法。  
- 完成後列入 checklist：§7 已含血緣；非線性待一句定稿口令  
- 待拍板：非線性要「定稿」還是先微調哪一段？
